# DocuLens - generated results report

_Generated by `doculens report`. Every number below is read from `results/results_long.csv`; nothing here is hand-entered._

## 1. Problem

Insurance claim intake in India receives claim forms and garage invoices as phone photographs and rescans: out of focus, noisy, skewed, unevenly lit and heavily recompressed. OCR on those images degrades badly, and every downstream step (field extraction, policy validation, settlement) inherits the error. This project asks a measurable question: **how much of that loss can classical digital image processing recover before the OCR engine ever sees the page?**

## 2. Data

- 18 synthetic documents evaluated on the `test` split (corpus of 60, split 50%/20%/30% train/val/test, fixed before any tuning).
- Document types: claim_form, invoice, rendered at 1240x1754 px with Faker `en_IN` content and exact ground truth.
- 16 capture conditions per document: the undegraded page plus 5 degradations (blur, jpeg, lowlight, noise, skew) at 3 severity levels each.
- Total evaluated rows: 1440 (5 methods x 288 images).

## 9. Limitations

- **Synthetic data.** Pages are rendered, not scanned. Real captures add paper texture, non-uniform ink, handwriting, stamps, staples, folds and perspective distortion that this corpus does not contain, so absolute CER here is optimistic.
- **One OCR engine.** All numbers are Tesseract `--oem 3 --psm 6`. A different engine would reorder the methods; preprocessing that helps Tesseract can hurt a learned recogniser trained on degraded inputs.
- **Degradations are applied one at a time.** Real photographs are blurred *and* noisy *and* skewed simultaneously.
- **Clean-page cost.** Preprocessing is not free: see the `none` row above for what the pipeline does to an already-clean scan.
- **Fixed parameters.** Stage parameters were chosen from the train/val split and not searched exhaustively; a per-degradation parameter sweep would likely improve every pipeline number.

## 10. Future work

The code is structured so that each of these plugs into an existing interface rather than requiring a rewrite (see `docs/EXTENDING.md`):

- A document classifier (CNN/ViT) choosing the pipeline per document type.
- Learned OCR (PaddleOCR, TrOCR) behind the same `OCREngine` protocol.
- Field extraction over the segmented regions, supervised by the `.json` ground truth this generator already writes.
- RAG over policy rules plus an agent loop for claim validation.
- An MCP server exposing `enhance_image`, `run_ocr`, `classify_document`, `extract_fields`, `search_policy_rules` and `validate_claim` as tools.
